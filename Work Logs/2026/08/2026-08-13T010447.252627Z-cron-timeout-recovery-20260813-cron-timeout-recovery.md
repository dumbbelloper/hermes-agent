## 내린 결정과 근거

- `HERMES_CRON_TIMEOUT`을 단순히 늘리지 않았다. 최신 장애는 장시간 계산이 아니라 unattended approval 대기였고, timeout 연장은 장애 감지를 늦출 뿐이기 때문이다.
- 게시 문서가 없는 irrelevant cycle에는 repository artifact와 외부 알림을 만들지 않도록 했다. 빈 PR 방지 계약과 일치하며 cron context와 실행 시간을 크게 줄인다.
- stale worktree는 모두 clean임을 확인한 뒤 제거했다. remote branch와 commit 삭제는 standing authorization 밖이므로 보존했다.
- 기존 live cron prompt는 임의 수정하지 않았다. 자동화 정책 자체 변경은 standing authorization 범위 밖이며, checked-in 변경의 PR 검토·merge 후 별도 운영 반영이 필요하다.

## 전역 설정이나 외부 시스템에 적용한 변경

- active automation run 3건을 controller의 terminal disposition으로 완료했다.
- stale local worktree 3개를 제거했다.

- 새 뉴스 문서·PR·Telegram 알림은 생성하지 않았다. 후보가 모두 결제 인프라 범위 밖이었기 때문이다.

## 알려진 한계와 남은 작업

- checked-in prompt 수정은 아직 live cron job의 저장 prompt에 반영되지 않았다. PR merge 후 `hermes cron edit` 또는 동등한 승인된 운영 변경이 필요하다.
- cron execution DB에는 과거 4회 timeout 이력이 그대로 남는다. 이는 감사 이력이며 삭제하지 않는다.
- 최신 source ledger 기준 processing item은 해소됐지만, 과거 retryable disposition 1건은 향후 source fingerprint 변화 또는 controller 정책에 따라 다시 후보가 될 수 있다.
- PR과 CI가 통과하기 전에는 안정화 변경을 production 적용 완료로 표시하지 않는다.
