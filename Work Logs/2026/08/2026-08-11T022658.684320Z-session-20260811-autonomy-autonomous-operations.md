## 내린 결정과 근거

1. Codex primary window 사용률이 80% 이상이면 새 agent 작업을 시작하지 않는다.
   - provider가 절대 token allowance 대신 percentage window를 제공하므로 native 단위를 사용하고 20% reserve를 남긴다.
   - 허용된 run도 1개 item만 queue해 3시간마다 quota를 다시 평가한다.
2. quota 조회 실패, primary window 누락, dirty worktree 또는 non-main coordinator는 fail closed한다.
   - 비용 상한과 사용자 변경 보호가 자동 PR 처리량보다 우선이다.
3. 자동 권한은 branch 생성, commit, `automation/*` push, PR 생성과 고정 Telegram recipient 알림까지로 제한한다.
   - 사용자가 반복 수행에 대한 standing authorization을 명시했지만 merge는 요청하지 않았으므로 자동 merge는 금지한다.
4. 각 병렬 task는 독립 worktree·branch와 독립 task log 파일을 사용한다.
   - root shared append log와 동일 checkout 수정이 주요 conflict 원인이기 때문이다.
5. clean `main` coordinator는 새 run 직전에 `origin/main`을 fetch하고 fast-forward-only로 자동 갱신한다.
   - 사람이 PR을 merge한 뒤 수동 `git pull`을 반복하지 않아도 다음 run이 최신 Vault를 기준으로 시작해야 하며, divergence는 자동 merge하지 않고 fail closed해야 하기 때문이다.

## 알려진 한계와 남은 작업

- bootstrap branch가 merge되고 root checkout이 clean `main`이 될 때까지 pre-run은 의도적으로 agent를 깨우지 않는다.
- Hermes gateway Telegram은 별도로 구성되지 않았으므로 성공 문서와 PR 알림은 프로젝트의 고정 Telegram notifier를 사용한다.
- Mac의 AC/Battery sleep이 1분으로 설정되어 있어 덮개를 닫거나 sleep 상태에서는 cron이 실행되지 않는다.
- cron agent의 첫 end-to-end delta 처리·worktree·push·PR·Telegram 경로는 bootstrap merge 이후 실제 신규 delta가 발견될 때 검증된다.
- 이번 bootstrap Telegram E2E는 one-off `notify-telegram` 경로를 검증했다. run ledger 기반 중복 방지는 실제 delta의 `automation-notify`가 처음 실행될 때 별도로 검증된다.
