## 사용자 요청과 목적

사용자는 자율 결제 뉴스 cron에 실패 이력이 반복되는 원인과 무인 자동화가 안정적으로 동작하지 않는 이유를 확인해 달라고 요청했다. 새 prompt 적용 후 발생한 timeout을 과거 실패와 분리해 조사하고, 닫힌 MacBook의 짧은 DarkWake에서 agent가 시작됐다가 다시 잠들어 timeout되는 반복을 방지하는 것이 목적이다.

## 수행한 변경

- probe를 5초로 제한하고 non-macOS, command failure와 malformed output에서는 기존 동작을 유지했다.
- closed-lid 판정과 외부 gate 선행 skip을 고정하는 regression test 두 개를 TDD로 추가했다.

## 내린 결정과 근거

- timeout 숫자를 늘리지 않았다. Mac이 잠든 동안 Python heartbeat와 tool timeout thread도 실행되지 않으므로 timeout 증가는 실패 시각만 늦춘다.
- `caffeinate`나 system sleep 정책을 자동 변경하지 않았다. clamshell sleep을 우회하는 전역 전원 변경은 사용자 시스템 전체에 영향을 주며 명시적 선택이 필요하다.
- closed clamshell에서는 정상 skip하는 fail-safe 기본값을 선택했다. 실패 이력과 stale lock은 막지만, 덮개가 다시 열릴 때까지 뉴스 처리가 지연된다는 한계는 문서에 명시했다.
- guard를 quota·Git·source 작업보다 앞에 배치했다. maintenance DarkWake의 약 45초 안에 결정론적으로 끝내기 위해서다.
- live cron은 merge되지 않은 controller를 사용하지 않도록 PR merge 전까지 paused 상태를 유지한다.

## 알려진 한계와 남은 작업

- 닫힌 clamshell에서는 해당 cycle이 처리되지 않고 다음 fully-awake cycle까지 지연된다. 정확한 시각의 상시 처리가 필요하면 항상 켜진 Linux server 또는 Mac mini가 적합하다.
- 이 변경이 main에 merge된 뒤 root를 fast-forward sync하고 cron을 resume해야 운영에 반영된다.
- merge 후 실제 installed wrapper가 `clamshell_closed`로 짧게 완료되는 execution을 확인해야 한다.
- 기존 실패 execution row는 감사 이력이라 삭제하지 않는다.
