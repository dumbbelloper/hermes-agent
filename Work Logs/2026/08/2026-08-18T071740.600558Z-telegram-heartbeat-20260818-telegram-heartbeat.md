## 사용자 요청과 목적

게시할 결제 뉴스 문서가 없는 cron cycle도 실제 실행됐다는 사실을 확인할 수 있도록 기존 고정 Telegram recipient에 간단한 heartbeat를 전송한다. 뉴스 가치가 없는 항목을 억지로 문서화하거나 Git·PR side effect를 만들지는 않는다.

## 수행한 변경

- [automation controller](../../../skills/hermes-news-automation/scripts/runtime/hermes_agent/automation.py)에 run 전용 Telegram heartbeat를 추가했다.
  - 문서가 없는 run에 run ID, 시작 시각, 수집 출처·실패 수, 후보 수, disposition 수, ledger 억제 수를 전송한다.
  - `run:<run-id>:telegram-heartbeat` delivery key를 선점해 같은 run의 재호출이 중복 전송되지 않게 했다.
  - timeout처럼 전송 결과가 불확실하면 `unknown`으로 보존하고 자동 재전송하지 않는다.
  - heartbeat `missing`·`sending`·`unknown` 상태는 final manifest를 `completed_with_exceptions`로 만든다. credential 또는 process launch가 reservation 전에 실패한 경우도 `missing`으로 durable manifest에 남는다.
  - 이미 `committed`, `notified`, `notify_unknown` 문서가 있는 run은 재호출돼도 잘못된 no-document heartbeat를 보내지 않는다.
  - pending·processing queue에서는 terminal 판정 전 heartbeat를 보내지 않는다.
- [precheck](../../../skills/hermes-news-automation/scripts/precheck.py)의 새 후보 0건 fast-path가 `automation-notify` 후 `automation-finish`를 실행하도록 변경했다. Telegram nonzero exit뿐 아니라 timeout·process launch 예외가 발생해도 logical lock finish를 시도한다.
- [cron prompt](../../../Automation/AUTONOMOUS_CRON_PROMPT.md), [Automation README](../../../Automation/README.md), [운영 가이드](../../../HERMES_AUTOMATION_GUIDE.md), [Skill 계약](../../../skills/hermes-news-automation/SKILL.md), CLI help를 새 정책과 동기화했다.
- TDD로 문서 없는 run heartbeat, run 단위 deduplication, unknown 보존, empty precheck 호출 순서, 기존 문서 전송과 retry 회귀를 검증했다.

## 내린 결정과 근거

- 게시 문서가 있으면 기존 문서 메시지가 실행 증거이므로 별도 heartbeat를 보내지 않는다. 게시 문서가 없을 때만 heartbeat 1건을 보내 메시지 중복을 피한다.
- delivery key는 시각이 아니라 run ID에 결합한다. scheduler retry와 명령 재호출에서도 같은 run은 한 번만 전송하기 위해서다.
- Telegram `unknown`은 재시도하지 않는다. API가 메시지를 전달한 뒤 응답만 유실됐을 가능성이 있어 중복 가능성을 우선 차단한다.
- heartbeat delivery가 `missing`, `sending` 또는 `unknown`이면 뉴스 처리 자체가 끝났더라도 durable run 상태는 `completed_with_exceptions`로 기록한다.
- Telegram 오류가 controller lock 해제를 방해하지 않게 finish를 항상 시도한다.
- 과거 작업 로그의 “Telegram 0건”은 당시 정책과 실제 결과를 기록한 역사 자료이므로 소급 수정하지 않았다.
