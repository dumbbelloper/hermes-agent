# Mapping PCI DSS v4.0.1 to the NIST Cybersecurity Framework 2.0

## 원문

- [원문 보기](https://blog.pcisecuritystandards.org/mapping-pci-dss-v4.0.1-to-the-nist-cybersecurity-framework-2.0)
- 발행: 2026-07-23
- 출처: PCI Security Standards Council / PCI Perspectives Blog
- 수집·검증: PCI SSC 공식 RSS에서 발견하고 공식 원문 확인

## 요약

PCI SSC는 PCI DSS v4.0.1 요구사항을 NIST Cybersecurity Framework(CSF) 2.0 결과와 연결한 mapping 문서를 발표했다. 이 자료는 2019년에 발표한 이전 버전 간 mapping을 갱신했으며, 조직이 두 체계에 공통으로 기여하는 보안 통제를 파악하고 평가·보고 중복을 줄이는 데 활용할 수 있다.

NIST CSF는 일반적인 사이버보안 위험 관리 결과와 공통 구조를 제공하고, PCI DSS는 결제 데이터를 저장·처리·전송하는 환경에 구체적인 보안 요구사항을 제시한다. 두 체계는 목적과 대상이 달라 서로 대체할 수 없으며 함께 사용할 때 보완적인 위험 관리 체계를 구성한다.

## 왜 중요한가

결제 환경을 운영하는 조직은 PCI DSS 준수와 전사 보안 프레임워크를 별도 활동으로 관리하기 쉽다. 공식 mapping은 하나의 통제 구현과 증거가 어떤 PCI DSS 요구사항과 NIST CSF 결과를 동시에 지원하는지 설명하는 공통 언어가 될 수 있다. 다만 mapping이 규제 또는 계약상 적용 범위를 대신 판정하지는 않는다.

## 기술 학습 키워드

- [[PCI DSS]] — 카드 소유자 데이터 환경에 적용되는 구체적인 보안 요구사항
- [[NIST Cybersecurity Framework]] — 조직 전반의 사이버보안 위험 결과를 관리하는 프레임워크
- Control mapping — 서로 다른 표준의 통제·결과 관계를 연결하는 작업
- Evidence reuse — 하나의 통제 증거를 여러 평가와 보고 목적에 재사용하는 방식

## 확인할 점

- mapping 원문에서 일대일·일대다로 연결되는 주요 요구사항
- 내부 통제 체계와 PCI DSS·NIST CSF 사이의 책임자와 증거 소유권
- mapping이 없는 요구사항과 별도 평가가 필요한 영역
- 법무·보안 책임자의 실제 적용 범위 검토
